NodePanel Vue Frontend Redesign
1. Design direction
NodePanel should remain a compact homelab control plane with a terminal-inspired identity, but it should stop behaving like a collection of independent forms.
The redesigned frontend should answer four questions immediately:
What does the factory believe exists?
What actually exists on the hypervisor?
Which machine am I currently targeting?
What operation is running, completed, blocked, or failed?
That directly reflects NodePanel’s two-source architecture: declared factory state from node manifests and actual state from libvirt.
The current frontend exposes both sources, but separates them into an Active Nodes card and a Hypervisor State table. This forces the operator to compare them manually.
The Vue version should reconcile them into one operational view.

Show payload state clearly:
APPROVED✓ bootstrap-agent.sh  SHA256 verified  Last reviewed: 2026-07-08DRAFT⚠ install-tools.sh  Not approved for executionUNAVAILABLE✕ old-worker-init.sh  Manifest mismatch
The README describes a three-tier picker and SHA-256 manifest gating. That security model should be visible in the UI instead of represented only by a select list.
Before firing, show:

payload name
checksum state
arguments
expected execution user
approval state
Disable execution when the backend reports that the gate is not satisfied.
Paste and execute
This is one of the highest-risk interfaces.
The current form allows pasted script, YAML, or commands to be submitted directly to the selected target.
The redesigned flow should require:
target selection
execution user confirmation
content preview
displayed command count or content size
explicit Run confirmation
For destructive-looking content, the frontend can show a warning, but the backend must remain the authority.
Do not pretend the browser can securely determine whether arbitrary shell content is safe.
Transfer
Show:
source folder name
file count
total size
target node
destination path
overwrite policy
transfer progress
The current directory input provides no visible transfer summary before submission.
6. Operation and job model
The current forms insert returned HTML into small output boxes such as #job-output, #fire-output, and #transfer-output.
Vue should replace this with structured jobs.
export interface OperationJob {  id: string  type: 'deploy' | 'fire' | 'transfer' | 'collect' | 'snapshot' | 'destroy'  target?: string  status: 'queued' | 'running' | 'succeeded' | 'failed' | 'cancelled'  progress?: number  currentStep?: string  createdAt: string  finishedAt?: string  summary?: string  output: JobOutputLine[]}
A mutation should return:
{  "job_id": "job_01J...",  "status": "queued"}
The frontend then tracks it through:
polling initially
Server-Sent Events later
or a dedicated operation WebSocket
Activity center
A persistent bottom bar should surface operations:
● DEPLOY worker-03       Running      Creating disk...✓ COLLECT worker-01      Completed    12 files collected✕ FIRE worker-02         Failed       SSH connection refused
Clicking an operation opens its complete output and ledger reference.
Do not mix structured operation logs with the interactive terminal. They serve different purposes.
7. Terminal redesign
Terminal header
SYSTEM TERMINALTARGET: worker-02SSH: sarge@192.168.122.42CONNECTED · 00:18:42[Reconnect] [Clear] [Pop out] [Full screen] [Change target]
The current terminal header only shows tty1 or connection status, while target selection is located in the hypervisor table.
Target identity must always be visible above the terminal.
Vue implementation
Use:
TerminalDock.vue└── useTerminalSession.ts
The composable owns:
xterm initialization
FitAddon

reconnect behavior
terminal resize
target changes
cleanup
Use ResizeObserver on the terminal container instead of relying only on window.resize and an arbitrary timeout.
Do not store the xterm instance or WebSocket inside Pinia. They are non-serializable runtime resources.
Pinia can store:
{  selectedTarget,  terminalOpen,  terminalWidth,  connectionStatus}
Existing target mismatch
The supplied node fragment posts several node actions into #terminal-output, but the main template defines #xterm-container and no #terminal-output element.
The Vue rewrite should eliminate DOM-target coupling entirely. Actions should update the operation store, not inject HTML into a named element.

12. Vue architecture
Recommended stack
Vue 3TypeScriptViteVue RouterPiniaxterm.jsTailwind CSS
Do not add Nuxt.
Do not add a large global component framework initially. NodePanel has a distinct visual system and only needs a modest reusable component layer.
Do not add Vue Query at the beginning. A typed API client plus feature stores is sufficient. Introduce a query library only when caching and invalidation become genuinely difficult.

13. Backend API changes
The current FastAPI routes return HTML fragments for HTMX. The migration should introduce JSON endpoints alongside them.
Suggested endpoints
GET    /api/v1/system/statusGET    /api/v1/nodesGET    /api/v1/nodes/:namePOST   /api/v1/nodesPOST   /api/v1/nodes/:name/actions/:actionGET    /api/v1/hypervisor/vmsPOST   /api/v1/terminal/targetGET    /api/v1/payloadsPOST   /api/v1/payloadsPOST   /api/v1/executionsPOST   /api/v1/transfersGET    /api/v1/jobsGET    /api/v1/jobs/:idGET    /api/v1/repositories/credentialsPOST   /api/v1/repositories/credentialsPOST   /api/v1/repositories/credentials/:id/scrubPOST   /api/v1/repositories/credentials/:id/nukeGET    /api/v1/ledgerGET    /api/v1/settingsPATCH  /api/v1/settingsPOST   /api/v1/settings/test-ssh
Action responses
Do not return presentation HTML.
Return structured results:
{  "ok": true,  "job": {    "id": "job_01J...",    "type": "collect",    "target": "worker-02",    "status": "queued"  }}
Errors should use a consistent format:
{  "ok": false,  "error": {    "code": "SSH_UNREACHABLE",    "message": "Could not connect to worker-02.",    "details": {      "host": "192.168.122.42"    }  }}
The frontend should not parse command output to determine success.
14. Migration strategy
Stage 1: foundation
Create frontend/ with Vue 3, TypeScript, and Vite.
Keep the existing HTMX interface available at /legacy.
Serve Vue at /app.
Add a Vite development proxy to FastAPI.
Introduce /api/v1/system/status.
Recreate the compact shell and persistent terminal.
No current feature is removed.
Stage 2: overview and reconciliation
Add JSON endpoints for manifests and virsh state.
Build the unified node inventory.
Add target selection.
Add the node inspector.
Keep actions linked to the existing backend functions.
This stage delivers the greatest usability improvement.
Stage 3: structured jobs
Wrap deploy, collect, snapshot, fire, and transfer operations in job records.
Add the activity center.
Replace injected HTML output.
Preserve raw output as structured job lines.
Stage 4: workflows
Migrate Deploy.
Migrate Fire Payload.
Migrate Transfer.
Migrate Paste and Execute.
Migrate Payload Upload.
Stage 5: repositories
Add JSON credential and worktree APIs.
Add safe scrub and nuke dialogs.
Ensure tokens never return to the browser.
Stage 6: ledger and settings
Add ledger filters and details.
Remove password retrieval.
Add SSH connection testing.
Add UI preferences and reduced-motion support.
Stage 7: cutover
Make Vue the default /.
Retain /legacy for one release.
Compare ledger records and action results between both interfaces.
Remove HTMX templates only after feature parity is verified.
15. Recommended first implementation slice
Do not start by converting all existing templates.
Build this vertical slice first:
Vue app shell
compact status bar
persistent xterm terminal
JSON manifest endpoint
JSON virsh endpoint
reconciled node table
target terminal action
collect action as a structured job
activity center
node inspector drawer
That slice proves:
Vue/FastAPI integration
the new state model
terminal persistence
operation handling
the new visual hierarchy
compatibility with the existing backend
Only after that should Repositories, Ledger, Config, and all five Toolbox workflows be migrated.
Final recommendation
NodePanel should not become a generic rounded-card SaaS dashboard.
Its strongest visual identity is the operator-console aesthetic, and that should remain. The redesign should make it feel like a serious control surface rather than a terminal-themed webpage:
compact system status
unified factory/hypervisor state
persistent selected target
persistent terminal
structured background operations
explicit drift
clear destructive-action boundaries
technical detail available on demand
The largest architectural improvement is not Vue itself. It is replacing fragment-driven DOM updates with an explicit frontend model for:
nodestargetsjobscredentialsaudit recordssystem status
Vue then gives that model a stable, maintainable interface.
